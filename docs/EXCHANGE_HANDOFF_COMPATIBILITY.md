# Способы передачи при обмене (2026-10)

## Объявление

В разделе «Что хотите взамен?» владелец выбирает один или несколько вариантов: `MEETING` (личная встреча), `DELIVERY` (доставка), `ONLINE` (цифровые товары/услуги). Настройки сохраняются в `Listing.exchangePreferences.handoffMethods`. У новых объявлений форма требует минимум один вариант; список отображается в публичной сводке.

Ранее размещённые объявления, у которых `handoffMethods` отсутствует, **не** считаются согласными на личную встречу. Их владельцы могут отредактировать объявление и выбрать варианты. JSON хранит настройки без миграции таблицы Listing.

## Предложение

Для каждой выбранной вещи обеих сторон собирается набор разрешённых способов. Обычный вариант возможен только при пересечении **всех** наборов. При выборе несовместимого способа интерфейс показывает предупреждение и предлагает явный запрос исключения.

Отдельная отметка инициатора сохраняется как `ExchangeOffer.handoffException=true`; сервер отвергает несовместимый метод, если согласие инициатора не было передано. Для согласованного метода пометка исключения не требуется и сервер её не примет.

Получатель видит, что предложенное условие нарушает настройки хотя бы одного объявления. Перед принятием он самостоятельно включает галочку `acknowledgeHandoffException`. Сервер не создаёт резерв без неё. Исключение относится только к этой конкретной версии предложения. Новые условия согласуются новым предложением, ранее подтверждённые условия после принятия не меняются.

При принятии повторно проверяются неизменность товаров и текущая совместимость. Любая попытка незаметно превратить неразрешённый метод в обычное предложение отвергается. Получение товаров подтверждается обычным для согласованного способа механизмом: QR для личной встречи, независимые подтверждения после доставки/исполнения онлайн.

## Ограничения

Это согласование между пользователями, не доказательство физической передачи и не гарантия денег. Актуальная версия не поддерживает смешанные способы по сторонам (например, один отправляет доставкой, второй передаёт лично), интеграции с перевозчиками или безопасную сделку.

## Безопасный выпуск

Сервер рекламирует `handoffPreferencesVersion:1`, публикация через новый веб-клиент блокируется, если подключён старый API, который проигнорирует новые настройки. В PostgreSQL добавляется только `ExchangeOffer.handoffException` с `DEFAULT false`. Миграция должна быть применена до включения соответствующего API.
