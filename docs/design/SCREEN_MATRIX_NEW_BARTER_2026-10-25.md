# БАРТЕР — экранная матрица нового дизайна (25.10.2026)

**Источник:** действующий master \`628c5a9\`, Next.js \`apps/web/src/app\`, октябрьская библиотека \`docs/design/barter-2026-10\`. Составлено по **реальному коду маршрутов и компонентов**, но без свежих браузерных скриншотов пользователя. Это инвентаризация, **не заявление о pixel-perfect готовности**.

## Контракт
1. Только **новый** БАРТЕР. \`screens/concept-v1\`, \`initial-overview.webp\`, сентябрьские изображения и старые навбары — **LEGACY / NOT A REFERENCE**; не удалять рабочую логику при их исключении из дизайна.
2. Нельзя переобозначать “есть файл” как “страница 1:1”. Статусы: **R** — эталон найден, **P** — эталон покрывает часть сценария, **M** — требуется поиск/создание отдельного эталона, **U** — служебный экран, решать по реальной UX-потребности, **QA** — визуальная/функциональная приёмка НЕ пройдена. Эталон не считается утверждённым, если нет подтверждения пользователя.
3. После инвентаризации создать **ровно один отсутствующий экран** в высоком разрешении, показать владельцу, и лишь после утверждения внедрять. Один экран ≠ коллаж. Не заменять проверенные октябрьские эталоны вновь сгенерированными.
4. Главный текущий блокер реального iPhone PWA — [issue #100](https://github.com/vraachmax/barter-marketplace/issues/100), где измерен 62px разрыв между системным экраном и браузерным viewport. Не объявлять закрытым через зелёный browser CI.
5. В общей оболочке не дублировать нижний navbar ни в одном экране; внутри открытой переписки dock скрыт согласно позднему утверждённому референсу.

### Неадресуемые подэкраны, которые нельзя забыть
- **Публикация \`/new\`:** 1 «Что предлагаете?» (R04 только визуальное направление); 2 «Категория и описание»; 3 «Фотографии»; 4 «Где находится»; 5 «Готово к публикации». Реальное \`TOTAL_STEPS=5\`, не сжимать до 3 ради картинки. Предложение обмена и выбор разрешённых способов передачи — отдельные состояния.
- **Настройки \`?section=\`:** \`account\`, \`storefront\`, \`appearance\`, \`notifications\`, \`privacy\`, \`security\`, \`about\`. Семь отдельных подэкранов/состояний, можно переиспользовать общий layout.
- **Аналитика:** \`overview\`, \`listings\`, \`audience\`, 7/30/90; не показывать несуществующие данные аудитории как реальные: код сейчас содержит явную заглушку.
- **Чат/обмен:** inbox → thread → предложение → выбор нескольких своих/чужих вещей → способ передачи → несогласованное исключение и взаимное одобрение → встречное/отказ → резерв → подтверждение QR или доставки/онлайн → отзыв → история. Текущая реализация \`chat-exchange.tsx\` имеет внутренние экраны \`info\`, \`search\`, \`media\`, \`listings\`, \`favorites\`, \`report\` и отдельные формы/обсуждения.
- **Управление объявлениями:** tabs по статусу, редактирование (ListingEditorDialog), продвижение (PromoteDialog), снятие/возобновление, решение при отсутствующих фото.
- **Поиск:** default/recent, auto suggestions, результаты, zero results, loading/retry, filter sheet, каталог-специфические атрибуты; не смешивать два разных механизма фильтров без проверки референса.
- **Общий словарь состояний:** первый визит, анонимный пользователь, данные загружаются, пустой список, сервер недоступен, запрещённое действие, keyboard/focus, loading CTA, длинное название, нет фотографии/аватара, недоступный способ обмена, light/dark.

Рабочий backend/история/права не должны ломаться ради совпадения с demo-макетом. Зелёная сборка не закрывает визуальную приёмку.

### Как закрывать backlog

1. Для каждого `MISSING` или недостающего состояния `PARTIAL` сначала проверить, не утверждался ли более поздний отдельный эталон; при отсутствии создавать **один отдельный референс**, не коллаж.
2. Представить владельцу на согласование. Только явное утверждение переводит `DRAFT → APPROVED`.
3. После внедрения проверять живой экран против утверждённого эталона с одинаковыми данными, mobile/desktop и light/dark, затем реальные действия, API и PWA на физическом iPhone. Только тогда `IMPLEMENTED → DEVICE VERIFIED / PIXEL ACCEPTED`.
4. Не менять production и не считать merge/CI завершением визуальной приёмки.

**Приоритет:** общий shell/PWA → главная → поиск/фильтры → карточка → 5 шагов публикации → чат/обмен → профиль/вложенные разделы → аналитика → остальные экраны.
