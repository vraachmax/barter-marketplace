# Barter — визуальная приёмка Claude v2 (18 октября 2026)

## Эталон

Файл пользователя: `barter-mobile(2).html`, SHA-256 `5ea0e0dec7c3fcf635ef1c8be616a21d939b0fce843330ed7c4100138ee3a12b`.

Эталон: **393 × 850 CSS px**, светлая и тёмная темы. В отличие от предыдущего прототипа, v2 включает `V.analytics` и `V.alisting` и использует **Inter**, а не Onest. Исходные токены: accent `#ff5a0a`, dark background `#0d0e0f`, dark card `#151618`, скругление карточек 18px, фото hero ~336px, 65px центральная FAB, блок tabbar из 5 колонок.

Снимки сняты из действительного HTML с локально отключёнными сетевыми ссылками на Google Fonts; шрифт разрешается установленными системными средствами. Изображения товара и категории сохранены неизменными.

## Методология

Визуальная оценка основана на:
1. Скриншотах исходного HTML v2 (обе темы, 393×850);
2. Скриншотах CI PR #77: Chromium 390 и WebKit 440; 
3. Фактических iPhone-скриншотах заказчика, ранее присланных в чате;
4. Инспекции Next.js компонентов и CSS. 

**Не путать браузерный зелёный CI с пиксельным совпадением.** Снимки CI используют фикстуры, часто без фотографий, с иными маршрутами и данными. Числовой pixel-diff возможен только на одинаковом viewport, тех же fixtures и том же состоянии UI.

## Дефекты нового прототипа (не переносить в приложение)

- `A.tile` не содержит изображения AirPods; `V.my` и `V.history` ломаются при обращении к `.src`. Требуется безопасный fallback.
- `tabsHtml()` связывает кнопку «Сообщения» с `tab('notif')` и экраном «Уведомления»; списку диалогов не предоставлен собственный дизайн.
- `act.cat` поддерживает только «Техника», остальные категории заглушки `toast`.
- `act.buy`, `act.attach` и часть управляющих действий содержат только toast, не настоящие сценарии API.
- Форма публикации является 3-шаговым демонстрационным UI без настоящей серверной проверки; требуется сохранить реальные зависимые атрибуты и валидацию.

## Приоритеты устранения

**P0 (перед релизом)**

1. Полностью унифицировать CSS мобильной страницы товара, убрать конфликты `globals.css` / `reference-fidelity.css` и правильно разместить фото, заголовок, цену, stats, продавца, specs и bottom CTA.
2. Обеспечить отсутствие PWA перекрытий с status bar, Dynamic Island, home indicator и клавиатурой на реальном iPhone.
3. Устранить дублирование кнопок избранного и закрепить единую навигационную семантику (открытая переписка не заменяет список диалогов).

**P1 (визуальное соответствие)**

4. Принять новые типографические токены Inter; отдельный commit в PR #77 изменил `layout.tsx`.
5. Выровнять пятёрку основных категорий по новому эталону; остальные категории должны оставаться доступными через функциональный раздел «Другое / Все категории», а не исчезать.
6. Добиться одинаковой геометрии карточек с настоящими фото и fallback-состояниями, без подмены данных.
7. Отдельно построить экран списка сообщений в стиле Claude v2, поскольку эталон его не содержит.
8. Отдельно сверить аналитику и статистику объявления после появления равных тестовых данных.

## Блокирующие критерии ручного одобрения

- Pixel comparison 393×850 и 430×932 для обеих тем на общих fixtures.
- Точно проверены типографика, размеры иконок, высота таббара, положение FAB, радиусы, отступы, масштаб товарных фотографий.
- Нет вертикального и горизонтального overflow; контент не перекрывает status bar и нижний gesture indicator.
- Работающие /favorites, /messages, /search, /new, галерея и действительный обмен; никакие функции не заменены демо-toast.
- На физическом iPhone подтверждены standalone PWA, Safari, клавиатура, swipe галереи и удержание превью.
- Финальные скриншоты одобрены отдельно, только затем merge + production deploy.

**Решение визуальной приёмки: NO-GO для заявления «1:1». PR #77 держать draft, production не затрагивать до закрытия P0 и визуального подтверждения.**
