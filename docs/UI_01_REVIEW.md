## Что проверено

Используется production-сборка web и реальные браузеры в GitHub Actions.
API и авторизация заменены изолированными браузерными фикстурами. PATCH сохраняет
данные в состоянии фикстуры, а после reload интерфейс получает их новым GET.
Это проверяет браузерный путь и контракт интерфейса, не настоящий Nest/PostgreSQL.

| Среда | Размер viewport | Темы |
|---|---|---|
| Chromium, desktop | 1280×900 | Светлая, тёмная |
| Chromium, tablet | 820×1180 | Светлая, тёмная |
| WebKit, mobile emulation | 390×844 | Светлая, тёмная |

Каждый из 6 прогонов проверяет:

- заполнение полей, размер текста ≥16px, поле ≥48px, радиус 16px;
- заголовок шапки 18px/600, заголовок раздела 20px, возврат ≥44px, CTA ≥52px;
- сохранение только имени/описания витрины и повторное чтение после reload;
- смену темы, PATCH только appTheme, reload и выбранное состояние;
- поле пароля и фокус, без отправки смены пароля;
- профиль → заказы → профиль → отзывы → профиль, перенос длинного отзыва;
- ошибку загрузки автоответа, сохранение витрины без его перезаписи;
- 401 при сохранении: черновик остаётся, вход возвращает в нужный раздел.

## Исправлено по результатам

1. Глобальные h1/h2/h3/h4 вне CSS-слоя имели приоритет над Tailwind-компонентами.
   На исходных снимках шапки получали 32px/bold вместо 18px/semibold.
   Базовая типографика перемещена в @layer base; явные размеры компонентов
   теперь работают. Дефолтные значения заголовков сохранены.
2. Выбор темы на телефоне занимал слишком много высоты. Теперь это три
   компактные строки с иконкой, подписью и состоянием; desktop сохраняет колонки.
3. В диапазоне 768–1023px профиль скрывал и мобильные ссылки, и desktop sidebar.
   Мобильная компоновка используется до lg, чтобы заказы/отзывы оставались доступны.
4. Первый тест 401 находил также Next route announcer. Локатор ограничен main;
   это ошибка теста, не новый дефект авторизации приложения.
