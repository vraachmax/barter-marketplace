# Общая модель объявления: первый блок, 2026-09-27

Максим подтвердил реализацию подробных ответов из разговора, после которых
просил сохранить решение в памяти. Этот блок закладывает модель для следующих
этапов. Подбор, справочники, аналитика и подтверждённая история сделок остаются
в плане и не объявляются готовыми по наличию переключателя.

## Сверка перед изменениями

| Часть | Было | Изменение | Проверка |
|---|---|---|---|
| Listing | Только attributes.isBarter, Market включал все записи | Два boolean-поля, один id, хотя бы один режим | PostgreSQL constraint, HTTP |
| Старые данные | Явный boolean opt-in в attributes | saleEnabled=true; barterEnabled из старого opt-in | Миграция существующей БД, строка «true» не считается согласием |
| Публикация/редактор | Галочка «рассматриваю обмен» | Продажа / обмен / оба, оценка для обмена | Unit, HTTP, WebKit/Chromium |
| Ленты/поиск/VIP | Только Barter имел фильтр допуска | Обе ленты фильтруются до подсчёта и страниц | Все сортировки, 2 страницы, устаревший индекс, VIP |
| Общие данные | Фото и избранное уже связаны с Listing | Переключение меняет поля той же записи | Фото, favorite и id после редактирования |
| Подбор и история | Полноценной модели сделки ещё нет | Следующий этап после полей намерения | В этом блоке не реализованы |

## Контракт и совместимость

- saleEnabled=true/barterEnabled=false: Маркет; false/true: Бартер; true/true: обе ленты.
- false/false, null, строки вместо boolean и конфликт с attributes.isBarter отклоняются.
- Старые клиенты могут передавать attributes.isBarter. Новые поля канонические;
  alias сохраняется для совместимости. SQL trigger поддерживает старые writers
  во время выпуска. Старые версии API не подходят для отката после появления
  exchange-only: они не умеют фильтровать Market по новому полю.
- Перед сохранением web проверяет /listings/capabilities. Старый API не должен
  молча принять публикацию, отбросив неизвестные поля. Данные остаются в форме.
- Существующая политика категорий сохраняется, включая отсутствие обмена
  у вакансий. Межкатегорийный обмен вещей не запрещается этой моделью.
- Market Meilisearch сохраняет текущий путь: сначала ограниченное окно id,
  затем проверка актуальных полей PostgreSQL, подсчёт и пагинация. Данные индекса
  не дают допуск в другую ленту. Barter пока использует PostgreSQL-поиск.
- Новый алгоритм ранжирования взаимных интересов не подменяется старым скорингом;
  он будет добавлен после структурированных пожеланий.

## Проверка и границы

Локально проверены вспомогательные web-контракты и синтаксис новых тестов.
В CI подготовлены PostgreSQL 16 rehearsal/backfill/restore, HTTP с настоящей БД,
регрессии поиска и браузерный редактор с перезагрузкой в обеих темах.
Результаты CI и production будут внесены после выполнения.
Реальные объявления не создаются для QA. Физический iPhone и работа из РФ
без VPN этим блоком не проверяются. UI-01/02 и PERF-01 не закрываются автоматически.
