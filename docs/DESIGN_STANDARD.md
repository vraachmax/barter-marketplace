# Barter: стандарт интерфейса v1

Проход 2026-09-10: стандарт перенесён в карточку объявления, витрину, кошелёк,
тарифы и действия контакта/отзыва/жалобы. Общий Card теперь имеет радиус 24 px.
Это статус реализации; полная визуальная приёмка всех состояний ещё не проведена.

Принят для реализации 2026-09-09 по запросу Максима. Приоритет над ранними
экспериментами и Avito-matched параметрами. Развивает уже выбранную белую основу,
Golos Text и стеклянный нижний хаб. Это web-адаптация принципов Apple, а не копия
нативного материала iOS.

## Сравнение ориентиров

| Система | Что берём | Как применяем в Barter |
|---|---|---|
| Apple HIG / Liquid Glass | Разделение управления и содержимого, ясная иерархия кнопок, удобная область касания | Стекло на шапках, навигации и панели действий; непрозрачные карточки и формы |
| Google Material 3 | Состояния элементов и адаптивное разделение списка и деталей | Видимые selected, disabled, loading, error; список диалогов и отдельная переписка на телефоне |
| Microsoft Fluent 2 | Семантические токены вместо индивидуальных цветов на каждом экране | Общая библиотека Button/Input/Textarea, цвета по назначению, одинаковые размеры |

Лучший вариант для текущего продукта: спокойная плоская основа плюс ограниченный
слой стеклянного управления. Это проектное решение по задаче, не утверждение о
существовании универсально лучшего дизайна. Не смешиваем зелёные, голубые и
оранжевые основные кнопки в одном режиме.

Контраст по формуле относительной яркости sRGB:
белый / #006BD6 = 5.15:1; белый / #B84617 = 5.35:1;
белый / #176CD1 = 5.12:1; #636D80 / белый = 5.21:1;
#A6B0C2 / #191E29 = 7.63:1.
Это проверка конкретных непрозрачных пар, не сертификат доступности всего сайта.
Ссылки на тёмной поверхности требуют отдельного светлого оттенка и проверки.
Цвета состояния сопровождаем текстом: ошибка, сохранено, недоступно.
Яркий голубой/оранжевый бренда сохраняем в оригинальном хабе и иллюстрациях.

## Кнопки

| Тип | Геометрия | Оформление |
|---|---|---|
| Сохранить / Опубликовать | минимум 52 px, ширина контейнера на телефоне | Сплошной цвет режима, белый текст 16 px / 600, capsule |
| Обычное действие | минимум 48 px | Primary по необходимости; одно главное действие на группу |
| Назад / Отмена | минимум 44–52 px | Нейтральная подложка или контур, основной текст |
| Кнопка с одной иконкой | область минимум 44×44 px | Круг, иконка 18–22 px, обязательное доступное имя |
| Фильтр / вкладка | минимум 44 px | Нейтральное состояние и мягкое выбранное состояние |

Размеры в таблице: наше решение для web в CSS px; рекомендация Apple 44×44 pt
не равнозначна CSS px на всех платформах.

Для «Сохранить» и «Опубликовать» текст достаточен: не добавляем декоративную
галочку, дискету или круг. Галочка обозначает уже достигнутый результат.
Во время действия меняем текст и блокируем повтор. Иконка загрузки допустима.
Убираем яркую цветную тень, scale-прыжки и тонкие случайные размеры.
В вертикальном flex-контейнере CTA не получает flex:1; min-height и shrink:0
гарантируют фактическую высоту. Общие размеры закреплены в ui/button.tsx.

## Поверхности, формы, текст

- Радиусы: карточка 24 px, поле 16 px, кнопка capsule; хаб сохраняет свои 28 px.
- Поля: минимум 48 px, текст 16 px, подпись снаружи, фокус и сообщение ошибки.
- Многострочные поля: минимум 112 px; не прячем длинный текст в однострочном input.
- Сетка отступов: 4, 8, 12, 16, 24, 32 px. На телефоне поля страницы 16 px.
- Иконки: один набор Lucide, обычно stroke 1.8; не смешиваем эмодзи с UI-иконками.
- Шрифт Golos Text сохранён; не переносим лицензируемые ресурсы Apple в web.
- Стекло: blur 18 px, без blur на каждой карточке. Opaque fallback и reduced
  transparency/motion уже предусмотрены в общих стилях.
- Вложенные разделы имеют общую шапку с возвратом; старое боковое меню не
  должно появляться над содержимым на телефоне.

## Что изменено в этом этапе

1. Общие Button/Input/Textarea, сохранение настроек, пароля, редактора и публикация.
2. Заказы и отзывы используют AccountScreenHeader; старое меню заказов удалено.
3. Тема применяется сразу, события обновляют переключатели, сеть не блокирует
   нажатие, localStorage ограничение не ломает текущую смену. Safari chrome
   получает цвет текущего фона вместо неизменно белого.
4. Вакансии: работодатель, сфера, адрес, зарплата до, период/частота выплат,
   сумма до/после налогов, занятость, формат, график, смена, вахта, оформление,
   опыт, образование, обязанности, допуски и условия. Поля состояния/доставки/
   торга не применяются. В основной цене вакансии вводится «Зарплата от».
5. Недвижимость/услуги больше не получают товарные общие поля; авто дополнены
   маркой, моделью и объёмом двигателя; услуги единицей цены и составом работ.
6. Дополнительные поля сохраняются в существующем attributes и читаются на
   странице объявления. Старые значения вакансий остаются читаемыми.

## Проверка и границы

Основание диагностики: текущие исходники и замечания владельца. Браузерный шаг
«Заказы» открыл гостевое состояние и потребовал вход. Авторизованные заказы,
настройки и работа клавиатуры iPhone не были доступны для полного визуального
аудита. Не выдаём исследование HIG или анализ исходников за такой аудит.

После выпуска проверить на iPhone: сохранение без сжатия, смена темы из двух
мест, возврат из заказов, вакансия с зарплатой за смену и вахтой.
Дальнейшая миграция отдельных legacy-контролов должна использовать этот
стандарт: карточка объявления, публичная витрина, кошелёк и тарифы. Общие
компоненты уже обновлены, но единообразие каждого состояния этих экранов
не подтверждено. Не объявляем весь продукт визуально принятым.
