# Единые характеристики, TXT-03, срез 1

Статус: подготовлено к CI, не считать опубликованным до записи в HANDOFF.

## Контракт

CatalogField хранит categorySlug, key, label, dependsOnKey и sortOrder.
CatalogOption хранит value/label, parentValue, enabled и sortOrder.
GET /categories/:id/attributes возвращает version:1 и fields с вариантами.
Идентификатор категории проверяется; неизвестная категория получает 404.
Namespace по slug не создаёт Category и не мешает bootstrap пустой установки.
Миграция добавляет только прежние варианты Barter для fuel, transmission,
body_type, drive в auto; внешние каталоги не копируются.

Форма, оба редактора и фильтры получают одну схему из API. Отсутствующая схема
или ошибка загрузки блокирует отправку до повторной загрузки. Зависимые поля
очищаются транзитивно при смене родителя. Старое значение явно помечается.
Поля имеют подписи, высоту 48px, общий цвет/радиус и состояния загрузки/ошибки.

API проверяет допустимые активные значения и связь с родителем. Неперенесённые
характеристики пока допускаются как раньше. Неизменённое legacy-значение можно
сохранить в прежней категории при неизменном родителе; новое неверное запрещено.

GET /listings принимает attributeFilters как JSON-объект строковых значений,
не более 16 полей, только со схемой выбранной категории. Неизвестные ключи,
значения, вложенные объекты и отсутствие категории отклоняются. Сравнение exact
по attributes JSON происходит до пагинации, count и VIP, включая stale Meili.
Ответ повторяет appliedAttributeFilters, чтобы frontend не выдавал старый API
за успешно отфильтрованную выдачу. Категория меняется: фильтры сбрасываются;
режим Market/Barter или сортировка меняются: фильтры сохраняются.

## Границы и следующий срез

Это не полный автокаталог. Марки/модели пока свободный текст; нужны проверенный
источник с правом использования, импорт, версия, зависимые модели/поколения и
постраничная загрузка большого справочника. Наследование схем подкатегориями,
характеристики остальных категорий и matching не реализованы. Публичная карточка
пока использует старые подписи тех же значений. Старые свободные значения
не конвертируются догадками и не совпадают с каноническими фильтрами.
Существующий лимит кандидатов Meilisearch не расширялся.

## Проверки

Unit: принадлежность, зависимости, legacy, невалидный JSON, сброс потомков,
замена статических полей схемой, навигация. HTTP в изолированной PostgreSQL:
схема, create/edit/readback, оба режима, пять сортировок, страницы, VIP и stale
индекс. Browser fixtures: выбор топлива при создании и фильтры с переключением
режима. Это не проверка production-аккаунта или физического iPhone.
