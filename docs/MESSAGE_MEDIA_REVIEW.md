# UI-02: изолированная проверка вложений

PR #29, ветка test/socket-conversation-acceptance. Не опубликовано.

## Изменения

Пустой файл и подпись неверного типа либо длиннее 4000 символов отклоняются
до обращения к хранилищу. При ошибке сохранения сообщения загруженный файл
удаляется; если удаление тоже завершилось ошибкой, пишется предупреждение
без URL или пользовательских данных. Исходная ошибка сохранения не скрывается.

## Приёмка

apps/api/test/messages-media.cjs использует настоящий Nest multipart endpoint,
Prisma/PostgreSQL и локальное файловое хранилище. HTTP guard заменён фикстурой;
проверка участия в чате настоящая. Создаются только изолированные CI-данные,
которые удаляются в finally. DATABASE_URL ограничен 127.0.0.1/barter_message_ci,
MEDIA_STORAGE_DRIVER=local, наличие BLOB_READ_WRITE_TOKEN запрещено.

Восемь групп:
1. PNG, подпись, реальные байты файла, запись БД и событие.
2. Заявленный video/mp4 и текст «Видео» без подписи.
3. Отсутствующий/пустой файл, SVG, подпись >4000 и повторённое multipart-поле.
4. Посторонний участник и запрос без тестовой авторизации.
5. Реальный multipart размером 40 МиБ + 1 байт, ответ 413 до хранилища.
6. Искусственный отказ upload, отсутствие сообщения/события.
7. Искусственный отказ на границе persistence после записи файла, удаление файла.
8. Искусственный отказ cleanup, предупреждение и успешная новая отправка после восстановления.

## Границы

Отказы storage/persistence вводятся тестовой обёрткой, это не настоящий сбой PostgreSQL
или Vercel Blob. Успешные записи выполняются в настоящей PostgreSQL.
Проверка MIME использует объявленный тип; видео содержит синтетические байты.
Декодирование, сигнатуры, воспроизведение и доставка из Vercel Blob не проверены.
При отказе удаления файл может остаться: добавлено наблюдение, не фоновый сборщик.
В конце теста такой файл удаляется настоящим локальным storage.

Повторы вложений после потери ответа всё ещё не идемпотентны. Успех новой отправки
после восстановленного сбоя не доказывает отсутствие дублей при неоднозначном ответе.
Browser reconnect/cookie, UI загрузки/повтора, реальные аккаунты, физический iPhone
и внешний health остаются открытыми. Frontend не менялся, browser suite/lint не запускались.
Публикация согласована после завершения раздела; текущий блок его не закрывает.
