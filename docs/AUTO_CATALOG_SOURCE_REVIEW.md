## Повторная проверка 2026-10-05

Редактор опубликован PR #49. Проверка закреплённого JSON выявила конкретные
пробелы, которые общий счётчик 308/5 455 не показывает:
- нет марок `tank`, `belgee`, `exeed`;
- `moskvich` содержит только 408/412, а не современную модель 3;
- у `geely` нет Monjaro/Coolray, у `haval` нет M6;
- `omoda/omoda-5` и `jaecoo/jaecoo-7` нельзя автоматически признать точными
  эквивалентами российского C5/J7 без проверки рынков и названий.
Это точечная проверка ожидаемых запросов, не процент покрытия или рейтинг продаж.

Актуальный SCHEMA.md VehiclesDB прямо отмечает поколения и варианты как
зарезервированные незаполненные слои. Схема не является готовыми данными:
https://github.com/vehiclesdb/vehiclesdb/blob/main/SCHEMA.md.
gor3a/vehicle-makes-models по-прежнему указывает autoevolution.com источником;
его LICENSE-DATA с ODbL не устраняет необходимость проверить права источника:
https://github.com/gor3a/vehicle-makes-models/blob/main/LICENSE-DATA.
Новый кандидат MeterApp/vehicle-db описывает разреженный граф поколений,
большинство записей не разрешается до поколения; ISC касается кода, а данные
остаются под условиями первичных источников. До импорта нужны закреплённый
снимок, проверка источников/условий, РФ-покрытие и mapping существующих ID:
https://github.com/MeterApp/vehicle-db#conservative-identity-resolution.
Ни один новый набор в этом проходе не импортирован, текущие ID не изменены.

Поколения и полнота остаются открытым требованием. Следующий реализуемый срез
TXT-03: структурированные пожелания с categoryId и текущими catalog values,
строгой проверкой родителей и совместимостью прежних пожеланий. Это не отменяет
дальнейшего наполнения поколений и не означает готовность matching.

Задача TXT-03 требует марку → модель → поколение и характеристики для рынка РФ.
Нельзя считать любой открытый список «всеми автомобилями». Версия набора,
происхождение, лицензия, пробелы и стратегия обновления являются частью импорта.

Ближайшая процедура: выбрать закреплённый релиз VehiclesDB, проверить наличие
приоритетных для РФ марок/моделей и список уведомлений об атрибуции, измерить
пропуски на контрольном наборе. Только затем импортировать с сохранением
стабильных значений и возможностью отключить/откатить релиз. Поколения и
комплектации требуют отдельного проверенного источника или самостоятельного
наполнения. Для уже опубликованных объявлений не менять значения без миграции.

Уточнение 2026-09-28: `ATTRIBUTION.md` проекта VehiclesDB требует видимую ссылку
на VehiclesDB при публичном использовании и сохранение уведомлений первичных
реестров, в том числе для коммерческого использования. Перед импортом нужно
закрепить конкретный tag/commit и контрольную сумму файла, сверить условия
релиза, разместить credits в web и будущем приложении, перечислить обязательные
уведомления источников и отметить преобразования. Указание одной ссылки на
VehiclesDB без этих уведомлений не завершает проверку. Источник:
https://github.com/vehiclesdb/vehiclesdb/blob/main/ATTRIBUTION.md.
