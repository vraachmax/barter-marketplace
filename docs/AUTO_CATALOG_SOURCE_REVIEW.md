# Источник справочника авто: первичная проверка 2026-09-28

Задача TXT-03 требует марку → модель → поколение и характеристики для рынка РФ.
Нельзя считать любой открытый список «всеми автомобилями». Версия набора,
происхождение, лицензия, пробелы и стратегия обновления являются частью импорта.

| Источник | Что подтверждено первичным источником | Вывод для Barter |
|---|---|---|
| Drom, правила портала: https://www.drom.ru/about/reprint/ | Правообладатель запрещает автоматизированное извлечение и воспроизведение данных без письменного разрешения. | Не копировать каталог или объявления оттуда. Референс UX не даёт права на данные. |
| NHTSA vPIC: https://vpic.nhtsa.dot.gov/api/ | Официальный API даёт марки, модели и выборку по году; источник предназначен для информации, поступающей от производителей в США. | Подходит как открытая дополнительная проверка make/model, но не покрывает поколения и российскую полноту. |
| VehiclesDB: https://github.com/vehiclesdb/vehiclesdb | Проект публикует версионированные марки/модели на CC-BY 4.0, с происхождением из официальных реестров 14 стран. Добавить credits в web и будущие приложения до использования данных. |
| gor3a/vehicle-makes-models: https://github.com/gor3a/vehicle-makes-models | Репозиторий заявляет ODbL и поколения, но README указывает компиляцию данных с autoevolution.com. | Не импортировать, пока происхождение и право на повторное распространение исходных данных не выяснены. |

Ближайшая процедура: выбрать закреплённый релиз VehiclesDB, проверить наличие
приоритетных для РФ марок/моделей и список уведомлений об атрибуции, измерить
пропуски на контрольном наборе. Только затем импортировать с сохранением
стабильных значений и возможностью отключить/откатить релиз. Поколения и
комплектации требуют отдельного проверенного источника или самостоятельного
наполнения. Для уже опубликованных объявлений не менять значения без миграции.

Уточнение 2026-09-28: `ATTRIBUTION.md` проекта VehiclesDB требует видимую ссылку
на VehiclesDB при публичном использовании и сохранение уведомлений первичных
реестров, в том числе для коммерческого использования. Перед импортом нужно
закрепить конкретный tag/commit и контрольную сумму файла, сверить условия
релиза, разместить credits в web и будущем приложении, перечислить обязательные
уведомления источников и отметить преобразования. Указание одной ссылки на
VehiclesDB без этих уведомлений не завершает проверку. Источник:
https://github.com/vehiclesdb/vehiclesdb/blob/main/ATTRIBUTION.md.

`e657ecee76b5cf795387084a17be69901f23bf87`, `manifest.json` Git blob
`2db740d138e0609c8be8769426cea94a06b90fe3`. Manifest указывает для
`car` **308 марок и 5 455 моделей**, но README той же версии указывает
**276 и 4 949**. Это разночтение нельзя превращать в утверждение о покрытии.
Файл `catalog/car/models.json` слишком велик для доступного чтения через
GitHub connector: возвращается пустое содержимое при наличии blob SHA
`206fc92fb2d2d4e8826dbd0e4a9cf729b027b061`. Целостность списка и
приоритетные для РФ модели пока не подтверждены. Импорт и публичное
использование данных отложены до получения полного файла, сверки checksum,
фактических записей и размещения всех уведомлений. README не заменяет manifest.
