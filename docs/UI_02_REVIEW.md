# UI-02: переписки и состояние клиента

Дата: 2026-09-19. PR: https://github.com/vraachmax/barter-marketplace/pull/27

## Изменения

- Черновики текста и вложений разделены по chatId в памяти открытой страницы.
- Запоздалые GET/POST не подменяют открытую переписку и не очищают чужой черновик.
- Мгновенная блокировка повторного нажатия отправки; явные ошибки и повтор загрузки.
- При ошибке отправки текст сохранён; при неопределённом результате предложено
  сначала проверить историю. Ограничение текста 4000 символов.
- chatId отражается в URL, работает возврат через историю браузера.
- Недоступный chatId и ошибка открытия по объявлению не заменяются другим чатом.
- Гостевой экран использует общую шапку и сохраняет адрес для возврата после входа.
- Исходная геометрия нижнего мобильного хаба сохранена.

## Границы и следующий шаг

Черновики не переживают reload/закрытие страницы. Серверный контракт не менялся:
если POST сохранён, но ответ потерян, повтор может создать дубль. Клиентская
блокировка двойного нажатия не заменяет серверную идемпотентность.
Реальные Socket.IO, доставка двум пользователям, отправка вложений и физический
iPhone с клавиатурой остаются открытыми. Реальных сообщений ради QA не отправляли.
Фикстуры не подтверждают сохранение в PostgreSQL. UI-02 полностью не закрыт.

Следующая доступная работа: серверная идемпотентность текстового
POST /chats/:id/messages. Повтор одной попытки после потери ответа должен вернуть
то же сообщение, новая отправка такого же текста должна создать новое.
Проверить параллельные повторы, границы пользователя/чата и потерянный ответ
на изолированных данных. Сначала изучить backend и схему, проверить
обратную совместимость контракта и миграции.
