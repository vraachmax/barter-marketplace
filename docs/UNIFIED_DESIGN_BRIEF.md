# Единый дизайн Barter / Market

Решение Максима, 2026-09-05. Статус: brief и варианты для выбора, не выпущенный редизайн.

## Область

Одна компонентная система для режимов «Бартер» и «Маркет», mobile и desktop,
светлой и тёмной темы. «Обе ветки» пока трактуем как эти два продуктовых режима.
Git-работа идёт в `feat/unified-design-search-plan`; master без слияния не меняется.
Главные пути: найти вещь, открыть объявление, предложить обмен/связаться,
опубликовать и управлять своим объявлением. Яндекс/платежи остаются отложенными.

## Не менять

- Логотип и существующий нижний mobile-хаб `MobileBottomNav`.
- Пять пунктов: Главная, Поиск, Объявления, Сообщения, Профиль; их порядок и маршруты.
- Хаб: боковые поля 12 px, высота внутреннего ряда 64 px, радиус 28 px,
  активный выступающий круг 52 px, top -20 px, цветное ядро с отступом 4 px.
- Хаб скрыт в `/new`, где свой action bar. Его поверхность и цвета можно обновлять.
- Существующие функции, данные, роли доступа и маршруты. Редизайн не повод скрыть настройки.

## Визуальное направление

Белая основа, Golos Text, чёткая иерархия, естественные фотографии. Liquid Glass
использовать как слой управления: хаб, search/filter bar, category controls,
всплывающие панели. Карточки и длинный текст имеют устойчивую почти непрозрачную
подложку. Это наша web-адаптация, не обещание нативной оптики Apple.

В документации Apple материал отделяет навигацию от содержимого; отсюда решение
не помещать весь каталог в несколько перекрывающихся стеклянных панелей.
Источник: https://developer.apple.com/design/human-interface-guidelines/materials

Начальные параметры для проверки, не утверждённые финальные значения:

| Токен | Светлая | Тёмная |
|---|---|---|
| page | #FFFFFF | #101318 |
| content | #FFFFFF | #1C222A |
| text | #17202B | #F4F7FA |
| muted text | #56616F | #B6C0CB |
| glass surface | rgba(255,255,255,.84) | rgba(28,34,42,.90) |
| glass border | rgba(255,255,255,.85) + внешний нейтральный контур | rgba(255,255,255,.18) |
| blur | 16–20 px только фиксированные контролы | 16–20 px |
| action accent | Market: холодный синий; Barter: тёплый оранжевый | соответствующий читаемый оттенок |

Точные акценты и контраст выбрать после визуального сравнения. Цвет не заменяет
названия режима, иконки и текст состояния. Не создавать второй набор JSX для режима.
Общие компоненты: AppHeader, CatalogSearch, CategoryGrid, ListingCard,
SettingsSection, EmptyState, ActionStatus, MobileBottomNav. Иконки одного набора.
Категории в две строки на mobile; только реальные категории API, горизонтальная
прокрутка доступна свайпом и клавиатурой. Без огромного hero над результатами поиска.

## Контракт каждой кнопки

| Элемент | Поведение |
|---|---|
| Настройки | `/profile/settings`; переключатели сохраняются через существующий API |
| Аккаунт / Приватность / Безопасность | `/profile/settings?section=account|privacy|security`, реальные секции |
| Заказы | `/profile/orders`, а не `/messages`; отдельно проверить полноту раздела |
| Отзывы владельцу | `/profile/reviews`; публичные отзывы проверять отдельно |
| Поддержка | существующий SupportSheet, не пустой обработчик |
| Избранное | POST/DELETE + состояние из API; не показывать успех без ответа |
| Предложить обмен | только после настоящей модели предложения, иначе не обещать действие |
| Назад на корне хаба | убрать: корневая вкладка не должна неожиданно уводить с сайта |
| Назад на вложенном экране | оставить с безопасным маршрутом родителя и сохранением формы |
| Ошибка действия | понятная причина, повтор; гость получает вход с сохранением контекста |

По исходникам сейчас настройки уже существуют, но «Поддержка» в mobile-профиле
не имеет обработчика; «Заказы» ведут в сообщения. Статическое «1,500 ₽» и имитация
пополнения в профиле требуют отдельной замены чтением реального кошелька, без
включения оплаты. Не считать этот аудит проверкой авторизованного пути в браузере.

## Доступность и проверки

- Контраст текста проверять на фактическом фоне под стеклом. Цели 4.5:1 для
  обычного текста, 3:1 для крупного текста и значимых границ/иконок.
- Зона касания не меньше 44×44 CSS px; явный focus и подписи icon-only кнопок.
- `prefers-reduced-motion`: убрать bounce, параллакс и длительные переходы.
- Для reduced transparency / отсутствующего backdrop-filter: непрозрачная поверхность.
  При отсутствии поддержки media feature дать настройку «Уменьшить прозрачность».
- Проверить ширины 360, 390, 430, 768, 1440; обе темы/режима, масштаб текста 200%.
- Safe area и клавиатура: хаб не закрывает отправку сообщения, фильтры и последний товар.
- Измерять скролл на реальном телефоне. Не ставить blur на каждую карточку списка.

## Порядок внедрения

1. Выбрать один из визуальных вариантов главной; зафиксировать снимок как target.
2. Общие tokens и shell, сохранить хаб; исправить маршруты и возврат.
3. Главная/поиск/карточки в обоих режимах, все состояния и адаптивность.
4. Профиль/настройки/избранное/объявления/сообщения и формы публикации.
5. Browser smoke на preview, проверки на телефоне, затем решение о выпуске.

Каждый блок отдельным проверяемым изменением. Три варианта нужны для выбора
материала и иерархии; новый интерфейс пока не переносить целиком в production.
