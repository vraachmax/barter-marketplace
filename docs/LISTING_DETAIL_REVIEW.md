# Экран объявления: аудит и исправления, 2026-09-13

Область: публичное объявление, связь, избранное, share, жалоба, отзыв, галерея.
Основа стиля: DESIGN_STANDARD.md. Apple-подобная спокойная база, стекло только
на навигации, общий Button и поля, радиусы 24px/16px/capsule.

1. Открытие объявления. В исходном desktop UI заглушка фото занимала большую
   часть экрана, заголовок и каждая группа имели отдельную рамку, seller/review
   использовали отличающиеся голубые акценты. Исходный снимок:
   [до исправлений](qa/listing-detail/barter-listing-01-before.jpg). Новая компоновка: заголовок отдельно, фото,
   единый блок цены/продавца, плоское описание и параметры. Mobile порядок
   установлен в DOM: фото → связь → описание; отдельный хаб сохранён.
2. Подтверждение жалобы. [Исходный снимок](qa/listing-detail/barter-listing-02-report-before.jpg):
   вопрос и «Да/Нет» встроены в тесную строку. Из кода установлено, что API
   возвращает ok=false, но обработчик выставлял done. Теперь общий диалог,
   выбор причины, честная ошибка/401, блок повторной отправки.
3. Связь и сохранение. Из кода: контакт терял next при входе, favorite только
   добавлял и не загружал начальное состояние. Теперь GET/POST/DELETE,
   восстановление пути после входа и отдельное управление для владельца.
4. Галерея/отзыв. Из кода: touch-none мешал прокрутке, dots были 6px, полноэкранный
   слой не ограничивал focus. Теперь pan-y, 44px, счётчик, native dialog.
   Отзыв использует общие поля, проверяет доступность, ошибки и повторные запросы.

Удалён «Документы проверены»: у блока не было подтверждающего поля API.
Карта больше не скрывает сломанную картинку за пустой подложкой: оставлена ссылка.
Это не подключение Яндекс API.

Проверки: 58 web tests; реальные обработчики report проверены на 500, 401,
повторную отправку и успех. Share проверен на отмену и запрет clipboard.
Макеты, DOM и компиляция не доказывают полную accessibility compliance.
Фото-галерея на реальных файлах, авторизованные сохранения/отзывы и Safari iPhone
нуждаются в отдельной пользовательской проверке. Жалобы и сообщения при QA
на production не отправляются.
